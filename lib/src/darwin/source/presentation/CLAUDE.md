# The Presentation layer

**Position.** Fourth of the four ([ADR 0024](../../../../documentation/adrs/darwin/four-layers-and-business-holds-the-session.md)): EmuKit, the SwiftUI views the macOS and iOS apps share — the first run and the BIOS pane, the library of games, the player and the acknowledgements screen, and the tokens they draw with. The apps themselves are targets in `lib/src/darwin/iStation.xcodeproj` (`lib/src/darwin/apps/`), the composition roots.

**Modules:** `styles` (the visual tokens from the design's tokens.json — palette (dynamic, three themes), theme, typography, metrics, motion, symbols — and the shared components), `bios` (the first run and the BIOS: Welcome, the BIOS check's job sheet over its own console session, and the BIOS pane, whose Run the BIOS powers the player's session on), `library` (the library of games: the sidebar's places, the games' table and grid, search, Game info, rename, remove and Locate…, Add Games…, Add Folder…'s scan job, and a PS-EXE's opening job, which powers the player's session on with the BIOS and the program), `player` (the player's screen), `acknowledgements` (every notice the app carries)

**Shape** ([ADR 0023](../../../../documentation/adrs/darwin/presentation-is-mvvm-and-styles-carries-the-design.md)): every module but `styles` is `Views/` + `ViewModels/`, with `Components/`, `Models/`, `Previews/` or `Debug/` only as real files need them. A view binds to its view-model, the view-model consumes Business (and Data's store where it keeps records, as `bios`'s do through `BIOSStorage` and `library`'s through `LibraryStorage`), and no file under `ViewModels/` or `Models/` imports SwiftUI, AppKit, UIKit or Cocoa. `styles` holds its tokens at its root, with `Components/`, `Models/` and `Previews/` only; it leans on no sibling, every other module may use it, and every color, font and size comes from it — and into it from the design's [`json/tokens.json`](../../../../documentation/design/darwin/json/tokens.json) first. Debug views live in `Debug/`, inside `#if PERSONAL_BUILD` ([ADR 0016](../../../../documentation/adrs/darwin/two-build-routines-and-a-fresh-start.md)).

**Seen on its own** ([ADR 0021](../../../../documentation/adrs/darwin/presentation-modules-stand-alone-and-preview-sample-data.md)): every module is its own SwiftPM target with its own test target; every view has named `#Preview`s per visible state, over the module's own fakes in `Previews/`, inside `#if DEBUG`.

**May depend on:** all four layers. Views and components import no Business module.

**Enforced by:** one SwiftPM target per module, generated from the module map in `lib/src/darwin/Package.swift`, and `ArchitectureTests` (`lib/src/darwin/tests/architecture/`), run by `swift test`.

**Changing this layer:** a new place is a module `source/presentation/<place>/` with `Views/` and `ViewModels/`, its `Module(.presentation, "<Name>", uses: […])` row in `Package.swift` and its place in the `EmuKit` product, its tests in `tests/presentation/<place>/` (and in the `macOS Personal` scheme), its own shared scheme (ADR 0017), its view-model built by the apps, a preview for every view it draws, and its name on this card's Modules line and in [ADR 0002](../../../../documentation/adrs/darwin/module-map.md)'s table.
